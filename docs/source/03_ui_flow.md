# UI-карта экранов и пользовательские сценарии

## Общий принцип интерфейса

Приложение должно быть рабочим инструментом для сотрудников СТО. Интерфейс нужен плотный, понятный, без лишней декоративности. Основной приоритет: быстро найти заказ, заполнить форму, прикрепить фото, увидеть рекомендации и итог.

## Основная навигация

Рекомендуемые разделы:

- Заказ-наряды.
- Автомобили.
- Рекомендации.
- Файлы.
- Пользователи, только для администратора.
- Настройки, только для администратора.

## Экран 1: список заказ-нарядов

Назначение: быстрый поиск и вход в работу.

Элементы:

- Поиск по номеру заказ-наряда.
- Поиск по гос. номеру.
- Поиск по VIN.
- Фильтр по статусу: открыт, в работе, закрыт.
- Кнопка создания заказ-наряда.
- Таблица заказов.

Колонки таблицы:

- Номер заказ-наряда.
- Статус.
- Автомобиль.
- Гос. номер.
- VIN.
- Пробег.
- Дата создания.
- Ответственный.

Основные действия:

- открыть заказ;
- создать новый заказ;
- изменить статус;
- перейти к сводке.

## Экран 2: создание заказ-наряда

Назначение: создать базовую запись, к которой дальше привязываются все документы.

Поля:

- Номер заказ-наряда.
- Статус, по умолчанию `open`.
- Марка и модель автомобиля.
- VIN.
- Гос. номер.
- Объём/мощность двигателя.
- Год выпуска.
- Пробег.

Поведение:

- Если автомобиль найден по VIN или гос. номеру, можно выбрать существующий.
- Если автомобиль не найден, создаётся новый.
- После создания пользователь попадает в карточку заказ-наряда.

## Экран 3: карточка заказ-наряда

Назначение: центральный экран работы с заказом.

Блоки:

- Заголовок: номер заказ-наряда, статус, автомобиль, гос. номер, пробег.
- Быстрые действия: акт осмотра, диагностика, рекомендации, фото/файлы, сводка.
- Последняя активность.
- Краткий список рекомендаций.
- Краткий список вложений.

Основные действия:

- открыть акт осмотра;
- открыть диагностику;
- добавить рекомендацию;
- загрузить файл;
- открыть сводку;
- закрыть заказ.

## Экран 4: акт осмотра автомобиля

Назначение: заполнить страницу 1 PDF-шаблона в структурированном виде.

Структура экрана:

- Левая колонка или верхние вкладки: секции формы.
- Правая/основная область: поля выбранной секции.
- Индикатор прогресса заполнения.
- Кнопки: сохранить, сохранить и выйти, перейти к следующей секции.

Секции:

- Общие данные.
- Секретки и запасные части.
- Внешний осмотр: передняя светотехника.
- Внешний осмотр: задняя светотехника.
- Щётки и омыватели.
- Подкапотное пространство.
- Итоговые рекомендации.

Поведение полей:

- `text`: обычный input.
- `text_multiline`: textarea.
- `number`: numeric input.
- `choice`: radio group или segmented control.
- `condition3`: три состояния: в порядке, рекомендуется принять меры, срочно.

Состояния `condition3`:

- `ok`: зелёный индикатор.
- `attention`: жёлтый индикатор.
- `urgent`: красный индикатор.

Полезные функции:

- Автосохранение черновика.
- Подсветка незаполненных обязательных полей.
- Возможность оставить поле пустым.
- Отображение последнего сохранённого значения.

## Экран 5: диагностика

Назначение: заполнить страницу 2 PDF-шаблона: ходовая, тормоза, трансмиссия, итоги.

Структура экрана:

- Список категорий диагностики.
- Табличный или карточный ввод по выбранной категории.
- Для элементов с `side: both`: отдельные колонки `Левая сторона` и `Правая сторона`.
- Для элементов с `side: none`: одна колонка состояния.
- Для элементов с `has_price: True`: поля цены запчастей и работ при статусе не `ok`.

Категории:

- Ходовая часть спереди.
- Ходовая часть сзади.
- Тормозная система.
- Стояночный тормоз.
- Трансмиссия.
- Итоги и развал-схождение.

Статусы диагностики:

- `ok`: исправно.
- `not_ok`: не исправно.
- `recommend_service`: рекомендуется заменить или обслужить.

Поведение:

- Если выбран `ok`, цены можно скрывать или блокировать.
- Если выбран `not_ok` или `recommend_service`, показывать поля `parts_price` и `service_price`.
- Для левой и правой стороны цены должны храниться отдельно.
- После заполнения категории пользователь может перейти к следующей или сохранить черновик.

## Экран 6: рекомендации

Назначение: управлять рекомендациями по заказ-наряду.

Список рекомендаций:

- Номер.
- Текст.
- Статус.
- Цена запчастей.
- Цена работ.
- Связанная диагностика, если есть.
- Автор.
- Дата создания.

Действия:

- Добавить рекомендацию.
- Редактировать текст.
- Изменить цену запчастей.
- Изменить цену работ.
- Изменить статус.
- Привязать к диагностике.

Статусы:

- `suggested`: предложено.
- `approved`: согласовано.
- `done`: выполнено.

Форма добавления:

- Текст рекомендации.
- Цена запчастей.
- Цена работ.
- Связь с диагностикой, опционально.

## Экран 7: фото и файлы

Назначение: хранить визуальные доказательства, документы и материалы по заказу.

Возможности:

- Загрузить фото.
- Загрузить документ.
- Загрузить видео.
- Добавить подпись.
- Привязать файл к заказу.
- Опционально привязать файл к акту, диагностике или рекомендации.

Список файлов:

- Превью для фото.
- Тип файла.
- Название файла.
- Подпись.
- Автор.
- Дата загрузки.

## Экран 8: итоговая сводка

Назначение: быстро увидеть состояние заказа и использовать данные для согласования с клиентом.

Блоки:

- Заказ-наряд: номер, статус, дата.
- Автомобиль: марка/модель, VIN, гос. номер, пробег.
- Акт осмотра: только проблемные или важные пункты.
- Диагностика: только `not_ok` и `recommend_service`, плюс цены.
- Рекомендации: список с ценами и статусами.
- Итоги: запчасти, работы, общая сумма.

Пример сводки:

```text
Заказ-наряд #12345
Автомобиль: Toyota Camry, гос. номер ABC-123, пробег 152000 км.

Акт осмотра:
- Ближний свет: urgent
- Охлаждающая жидкость: ниже нормы, рекомендуем диагностику

Диагностика:
- Амортизатор передний левый: not_ok, запчасти 10000, работы 3000
- Передние тормозные колодки: recommend_service, запчасти 5000, работы 1500

Рекомендации:
1. Заменить передние амортизаторы, suggested, запчасти 20000, работы 6000
2. Заменить передние колодки, approved, запчасти 5000, работы 1500

Итого: запчасти 25000, работы 7500, всего 32500.
```

Действия:

- Распечатать.
- Экспортировать PDF.
- Отправить клиенту, если появится клиентский канал.
- Перейти к редактированию акта, диагностики или рекомендаций.

## Экран 9: пользователи и роли

Назначение: управление сотрудниками.

Доступ: только администратор.

Поля пользователя:

- ФИО.
- Роль.
- Телефон.
- Email.
- Telegram ID, опционально.
- Активен/не активен.

Действия:

- Создать пользователя.
- Изменить роль.
- Деактивировать пользователя.
- Посмотреть историю действий.

## Основные пользовательские сценарии

## Сценарий: создать заказ и заполнить акт

1. Пользователь открывает список заказов.
2. Нажимает `Создать заказ`.
3. Вводит номер заказ-наряда и данные автомобиля.
4. Открывает карточку заказа.
5. Переходит в `Акт осмотра`.
6. Заполняет секции по порядку.
7. Сохраняет акт.
8. Возвращается в карточку заказа.

## Сценарий: заполнить диагностику

1. Пользователь открывает карточку заказа.
2. Переходит в `Диагностика`.
3. Выбирает категорию.
4. Для каждой позиции выбирает статус.
5. Для позиций с проблемами вводит цену запчастей и работ.
6. Заполняет итоги, развал-схождение и исполнителя.
7. Сохраняет диагностику.

## Сценарий: добавить рекомендацию

1. Пользователь открывает карточку заказа.
2. Переходит в `Рекомендации`.
3. Нажимает `Добавить`.
4. Вводит текст рекомендации.
5. Вводит стоимость запчастей и работ.
6. Сохраняет рекомендацию со статусом `suggested`.

## Сценарий: согласовать рекомендацию

1. Мастер открывает рекомендации заказа.
2. Выбирает рекомендацию.
3. Меняет статус на `approved`.
4. После выполнения работ меняет статус на `done`.

## Сценарий: прикрепить фото

1. Пользователь открывает карточку заказа.
2. Переходит в `Фото и файлы`.
3. Загружает фото.
4. Добавляет подпись.
5. Фото появляется в списке вложений заказа.

## Сценарий: посмотреть итог

1. Пользователь открывает карточку заказа.
2. Переходит в `Сводка`.
3. Видит проблемные пункты акта, диагностики и рекомендации.
4. Проверяет итоговую стоимость.
5. Экспортирует или печатает сводку.

## Рекомендации по UX

- Для диагностики лучше использовать таблицу, а не пошаговый мастер: сотруднику быстрее видеть сразу много позиций.
- Для мобильного интерфейса можно оставить пошаговый режим.
- Для desktop-интерфейса категории диагностики должны быть вкладками или боковым меню.
- Цвета статусов должны быть едиными во всём приложении.
- Все формы должны поддерживать черновик и ручное сохранение.
- Сводка должна показывать не все поля, а только проблемные и важные пункты.
